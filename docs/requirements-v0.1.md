## 1. 背景与目标

**痛点**：Mentor 希望 Lia 每天分享学习内容，但 Lia 经常忘记手动汇报。

**产品目标**：一个公开的 "Today I Learn" 网页。每天 Lia 和 Claude 对话确认学习进度，由 Claude 完成内容更新；Mentor 打开固定 URL 就能看到当天学习成果。

**学习目标**（同样重要）：借这个项目走通 **网页部署 + 前后端交互的全流程**。

> ⚠️ 这两个目标有时会打架：产品上「最快上线」的方案是纯静态页面，但那样就学不到后端了。本文档的 Phase 划分会兼顾两者：内容走 Git + 静态渲染（快），进度数据继续走你已有的 Express + Neon 后端（保留学习价值）。

**时间预期**：「尽快做出来」→ 🟡 见 §5-I，需要一个具体数字才能决定 Phase 1 砍多少。本文档暂按 **1–2 周业余时间** 规划。

## 5. 🟡 模糊点 — 需要你拍板的 10 个问题

每条给了默认建议；你后续的需求文档里如果没覆盖这些点，我会再指出来。

### A. 数据的 single source of truth 是哪个？
口述里出现了 **4 个存储**：Notion、Neon Postgres、GitHub repo、你的本地电脑。谁是主、谁是镜像？每多一个镜像就多一条要维护的同步链路，这是这类个人系统最常见的烂尾原因。
**默认建议**：内容（TIL 文章、计划）以 **repo 里的 markdown 为唯一主存储**；结构化进度（LC 勾选）以 **Postgres 为主**；Notion 和本地只做可选下游，不做双向。

### B. 「实时展示」到底多实时？
真·实时（WebSocket/推送）和「我更新后 Mentor 刷新就能看到」是两个量级的工程。你的更新频率是每天 1 次。
**默认建议**：按「分钟级」理解——push 后自动重新部署（约 1 分钟生效）即满足需求。文档里不再使用「实时」一词，改为「当日更新当日可见」。

### C. 「整合学习资料」具体指什么？
链接列表？笔记全文？还是要上传 PDF/文件？这三者的成本差一个量级（文件上传需要对象存储 + 访问控制）。
**默认建议**：Phase 1 = 外部链接 + markdown 笔记。文件资料留在本地或网盘，网页只放链接。

### D. GRE 和 PhD 申请的「进度」怎么量化？
LC 有题号可以数；GRE 是背词数？TOEFL/GRE 模考分数？刷题套数？PhD 申请是 checklist（选校清单 / 文书状态 / 推荐信状态 / 网申提交）？**追踪进度的前提是每个 track 有可量化的字段**，否则没法建表也没法画进度条。
**默认建议**：每个 track 先定 2–3 个最粗粒度指标即可，如 GRE = {当前阶段, 单词进度 x/y, 最近模考分}；PhD = {阶段 checklist 完成 n/m}。

### E. Mentor 访问 = 全网公开吗？
公开 URL 意味着**任何人**（包括未来雇主、现在的同学）都可能看到。「PhD 申请进行中」「在刷题找工作」这类信息本身就是半敏感的，即使不含简历。
**默认建议**：Phase 1 接受「unlisted 公开」（不挂搜索引擎、只把 URL 给 Mentor），PhD track 在页面上只展示脱敏后的阶段进度（如「文书 2/3」），不出现学校名。真正的访问控制放 Phase 2。**这条请明确表态，它决定 PhD track 上什么内容。**

### F. 「给 Claude access 直接 modify」——通过什么通道改？
三个候选：(a) Claude 改 repo 内容文件 → git push → 自动部署；(b) Claude 调后端受保护 API 写数据库；(c) Claude 写 Notion、网页从 Notion 拉。
**默认建议**：**(a)**。理由：免费获得版本历史 / diff / 回滚（正好满足 R5）；不需要先解决 API 鉴权；就是现在这个 Cowork 会话已经能做的事（我已能读写你的 lia-til 文件夹）。(b) 是很好的 Phase 2 学习素材——做它之前必须先学 auth，因为**公网上无鉴权的写接口 = 任何人都能改你的网页**（v1 的 toggle 接口部署后就有这个问题，Phase 1 需处理，见 §7）。(c) 见 §6.1。

### G. 「LeetCode API」不存在官方版
LeetCode 没有官方公开 API，只有非官方 GraphQL endpoint 和第三方封装：能用，但不稳定、可能限流、随时可能失效。要不要接受这种脆弱依赖？
**默认建议**：Phase 1 不接。每天你口述（「今天 LC 3 道」），我写入。Phase 2 再做定时拉取作为 cron + 外部 API 的学习素材，坏了也不影响主流程。

### H. 「敏感文件 skip 掉」靠什么保证？
靠每次记得，还是靠机制？
**默认建议**：机制化——repo 里约定 `content/`（可发布）与 `private/`（永不发布，写进 `.gitignore`）两个目录；我更新内容时只碰 `content/`。另外 `backend/.env` 里有数据库连接串，**需要立刻确认它在 `.gitignore` 里且从未被 commit 过**（backend 下已有 .gitignore，但内容待验证；如果已进 git 历史，要换 Neon 密码）。

### I. 「尽快」= 多快？
几天、两周、还是一个月？这直接决定 Phase 1 的范围。另外每天能投入多少时间（这个项目本身也在和 LC/GRE 抢时间）。
**默认建议**：Phase 1 目标 **2 周内 Mentor 拿到可用 URL**，其中第 3–4 天就先上线一个最小版本（哪怕只有 LC checklist + 一段当日 TIL 文字）。

### J. 部署到哪里？
前端静态页和后端 API 是分开部署的两件事。候选：前端 GitHub Pages / Vercel / Netlify；后端 Render / Railway / Fly.io（免费层均可）；数据库已经在 Neon。要不要自定义域名？
**默认建议**：前端 Vercel（push 即部署，正好演示 CI/CD），后端 Render 免费层，暂不买域名。都在免费额度内，$0 成本。

## 6. 🔴 不切实际 / 建议移出 Phase 1 的功能

### 6.1 Notion 同步 —— 建议整个砍掉（最重要的一条）
口述里的核心闭环是「你告诉我 → 我更新 → Mentor 在**网页**上看」。注意：**Notion 在这个闭环里不承担任何角色**——Mentor 看的是网页，你记录靠对话，存储在 repo/DB。它是第三份需要保持同步的拷贝，而多端同步是这类项目最容易烂尾的部分（冲突、格式漂移、API 限额）。
**建议**：Phase 1 完全不做。如果你对 Notion 有独立需求（比如自己习惯在 Notion 里看），Phase 2 做**单向导出**（网页数据 → Notion，只推不拉），永远不做双向。
*如果我理解错了——比如 Mentor 实际上习惯看 Notion、网页反而是次要的——那架构会反过来（Notion 为主存储，网页从 Notion API 读），请纠正我。这是需要你确认的隐藏前提。*

### 6.2 「实时」推送 —— 不必要
每天更新一次的内容不需要 WebSocket / SSE。push 后 1 分钟内生效已超出实际需求。（§5-B）

### 6.3 LeetCode 自动拉取 —— 移到 Phase 2
依赖非官方 API，脆弱；且你已有更可靠的输入通道（每日对话）。（§5-G）

### 6.4 完整的资料 Warehouse（文件上传、全文搜索）—— 移到 Phase 2/3
Phase 1 的「warehouse」= 结构化的 markdown 目录 + 链接。搜索靠浏览器 Ctrl-F 和 GitHub 搜索已经够用。

### 6.5 给 Claude 长期写权限的自动化管道 —— 移到 Phase 2
「给我一个永久 token 让我直接写生产数据库」在没有鉴权体系之前是危险的。Phase 1 用 Cowork 会话 + git push 就能达成同样效果，且每次改动都有 commit 记录可查。（§5-F）

### 6.6 进度可视化图表（heatmap、趋势图）—— 移到 Phase 2
先有数据，再谈图。Phase 1 用数字和简单进度条（v1 已有）。

## 7. 建议的 Phase 划分（基于现有 v1 演进）

### Phase 1 — Mentor 能用（目标：2 周）
1. **repo 整理**：确认 GitHub 远端；`content/` vs `private/` 目录约定；验证 `.env` 未泄漏。
2. **部署现有 v1**：前端上 Vercel、后端上 Render、连 Neon——这一步就走完了你想学的部署全流程。给 v1 的 toggle 写接口加一个最简单的 API token 校验（防止公网任何人改你的勾选）。
3. **TIL 展示**：新增页面/区块——今日 TIL（markdown 渲染）+ 历史列表 + 三 track 状态概览（由 `content/` 下的 markdown / JSON 驱动）。
4. **每日流程跑通**：你和我对话 → 我更新 `content/` 下的文件 → push → 自动部署 → Mentor 刷新可见。
5. **验收标准**：Mentor 拿到一个 URL；连续 5 天流程无需你碰 GitHub；页面上无隐私信息。

### Phase 2 — 更顺手（Phase 1 稳定跑 2 周后再启动）
- 受保护的内容写 API（学 auth）；TIL 入库
- LC 定时拉取（学 cron + 外部 API 容错）
- Notion 单向导出（如仍需要）
- 进度图表 / heatmap
- 访问控制（如 §5-E 决定需要）

### Phase 3 — 可选
- 全文搜索、资料文件库、自定义域名、多用户（如果想给别人用）

## 8. 非功能性需求

- **成本**：全程 $0（Vercel / Render / Neon 免费层）。
- **维护**：单人项目，任何组件坏了不影响你继续学习（内容永远在 git 里，最坏情况 Mentor 直接看 GitHub）。
- **隐私**：靠目录机制保证（§5-H），不靠记忆。
- **可靠性**：无 SLA 要求；部署挂了第二天修即可。
