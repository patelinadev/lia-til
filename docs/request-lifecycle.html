Auth request · lifecycle

One request, three lanes

You open /private/applications while logged in. Follow it top-to-bottom — the color of each step tells you which machine runs it. Notice that every trust decision happens on a server, never in your browser, and FastAPI only shows up at the very end.

Browser
You click the corner 🔒 → the browser sends GET /private/applications. The lt_session cookie rides along automatically with the request.
The browser only sends the request + later displays the result. It makes no decisions. ↓ handoff to the Vercel server

The page runs on the server as a Server Component. First line: await requireAdmin().

3
Vercel server
getSession() reads the cookie and verifies the JWT signature with AUTH_SECRET. Valid → it's you. ✓
lib/session.ts · jose jwtVerify (HS256) AUTH_SECRET lives only here, on the server — so the browser can't forge the cookie. This is the whole security.
4
Vercel server
Session ok → fetch the real data: getFullApplications() calls FastAPI, sending the header x-admin-secret: BACKEND_SECRET.
lib/private.ts · server-to-server fetch BACKEND_SECRET travels server → server only. It never touches the browser. ↓ now — and only now — FastAPI is involved
5
FastAPI + Neon
require_admin checks the secret matches → queries the Neon database → returns the full rows as JSON.
backend/main.py · /api/applications/full Fail-closed: wrong/absent secret → 401, no data leaves. ↑ JSON back to the Vercel server

Vercel server
The server builds the finished HTML with the data baked in, and sends it to the browser.
7
Browser
The browser displays the page. Interactive bits (the ApplicationsExplorer — a Client Component) then "hydrate" so filtering/sorting works.
Only now does code run in the browser — and it's just UI, never the auth check.
Branch · not logged in (incognito)

At step 3, an incognito window has no cookie → getSession() returns null → requireAdmin() does redirect("/api/auth/login") → the browser is bounced to GitHub. Steps 4–7 never run; FastAPI and the database are never touched. The private data never left the server.

The three things to remember

  • Color = machine. Green steps run on the Vercel server (Next's server half), grey on your browser, amber on FastAPI. "It's in the web/ project" doesn't mean "it runs in the browser."
  • Secrets never reach the browser. AUTH_SECRET (verifies the cookie) and BACKEND_SECRET (opens the data endpoint) both live server-side only. That's why tampering with the cookie fails.
  • FastAPI is the last lane, and optional. The whole auth check finishes on the Vercel server; the data backend is only reached after you're verified — and skipped entirely if you're not.

One line: browser asks → Vercel server decides who you are (cookie + AUTH_SECRET) → Vercel server fetches data from FastAPI (with BACKEND_SECRET) → browser shows the result. Trust always lives on a server.
