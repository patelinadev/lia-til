🔑 Two gates, two different secrets — and neither ever reaches your browser

1AUTH_SECRET signs & verifies your session JWT on the Vercel server — it proves “you are the admin.” Fail → 307 to login, and FastAPI is never called.
2BACKEND_SECRET is the x-admin-secret header on the server→FastAPI call — it proves “this call is from our own server.” Server-to-server only; the browser never sees it.

Why you never "see" the 307

A redirect is a normal HTTP response — the browser follows it on its own, so you only land on the final page (the GitHub login), never a "307" screen. The server says "not here, GET this other URL instead", and the browser silently sends that next request. That is exactly what you described — you reverse-engineered the 307. To actually watch it: DevTools → Network (tick "Preserve log") → you'll see /private 307 → /api/auth/login 307 → github.com.

Incognito has three states — the branch above is only the first:

① before login → no cookie → 307 to login · ② logging in → the callback sets the cookie in this incognito session · ③ after login, same window → cookie present → the page renders (no 307). A brand-new incognito window is back at ① and re-asks you to log in — that's correct, not a bug (no cookie = must authenticate).

Branch · not logged in (incognito)

Everything is the same until step 3. An incognito window sends no cookie:

// lib/session.ts const token = (await cookies()).get("lt_session")?.value; // undefined if (!token) return null; // getSession() → null // lib/auth.ts isAllowed(null) → false → currentAdmin() → null if (!session) redirect("/api/auth/login"); // requireAdmin bounces you

→ the server returns HTTP 307 → /api/auth/login. Steps 4–7 never run. FastAPI and the database are never touched.

Read it as three columns of value

  • Cookie in (step 1) → the browser's only job: send the request + the lt_session JWT.
  • Session out (step 3) → getSession() turns that cookie into { login, name, avatar } — or null. This decides everything.
  • Data out (step 5) → FastAPI returns { total, applications: [...] }, but only after the secret matches. Reached only if step 3 said "yes".
