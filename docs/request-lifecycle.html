Browser
You click the corner 🔒. The browser sends the request; the session cookie rides along automatically.
# the HTTP request the browser sends GET /private/applications Cookie: lt_session=eyJhbGciOiJIUzI1NiJ9.eyJsb2dpbiI6… # the JWT, auto-attached
↓ travels to the Vercel server
2
Vercel server
The page runs on the server (a Server Component). Its first line asks "is this the admin?"
// app/private/applications/page.tsx const session = await requireAdmin();
↓ requireAdmin lives in lib/auth.ts → calls lib/session.ts
3
Vercel server
Read the cookie & verify its signature.
// lib/session.ts — getSession() const token = (await cookies()).get("lt_session")?.value; const { payload } = await jwtVerify(token, key()); // key() = AUTH_SECRET
→ returns { login: "patelinadev", name: "Lia", avatar: "…" } or null if the cookie is missing / tampered / expired
// lib/auth.ts — is it the ONE allowed login? isAllowed(session) → "patelinadev" === ALLOWED_GITHUB_LOGIN → true
→ requireAdmin returns the session → the page keeps going. // if it were null: redirect("/api/auth/login") — see branch below
app/private/applications/page.tsx · lib/auth.ts · lib/session.ts
4
Vercel server
Session ok → now fetch the real data from the backend.
// app/private/applications/page.tsx const apps = await getFullApplications(); // lib/private.ts — the actual call it makes: fetchJsonWithRetry( "https://lia-til.onrender.com/api/applications/full", { headers: { "x-admin-secret": BACKEND_SECRET } } // secret, server→server only );
↓ now — and only now — FastAPI is involved
5
FastAPI + Neon
Check the secret, query the database, send JSON back.
# backend/main.py — require_admin (the gate) if not ADMIN_SECRET or x_admin_secret != ADMIN_SECRET: raise HTTPException(status_code=401) # secret matches → pass # then applications_full() queries Neon and builds the rows
→ the server returns this JSON: { "total": 129, "applications": [ { "appNum": 1, "company": "…", "role": "…", "status": "…", "notes": "…" }, … 128 more … ] }
↑ JSON travels back to the Vercel server

Vercel server

Branch · not logged in (incognito)

Everything is the same until step 3. An incognito window sends no cookie:

// lib/session.ts const token = (await cookies()).get("lt_session")?.value; // undefined if (!token) return null; // getSession() → null // lib/auth.ts isAllowed(null) → false → currentAdmin() → null if (!session) redirect("/api/auth/login"); // requireAdmin bounces you

→ the server returns HTTP 307 → /api/auth/login. Steps 4–7 never run. FastAPI and the database are never touched.

Read it as three columns of value

  • Cookie in (step 1) → the browser's only job: send the request + the lt_session JWT.
  • Session out (step 3) → getSession() turns that cookie into { login, name, avatar } — or null. This decides everything.
  • Data out (step 5) → FastAPI returns { total, applications: [...] }, but only after the secret matches. Reached only if step 3 said "yes".
